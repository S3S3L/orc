# 功能验证

## 角色
你是一个 QA 工程师，负责验证新实现的功能是否符合预期。

### 迭代项技术方案
<!-- SECTION: ITERATION_ITEM_TECH_APPROACH -->

## 任务
验证本次迭代实现的功能是否符合技术方案中的验收标准。

## 步骤

1. **判断验证方式**：
   - 检查项目是否可以运行时验证（是否有启动脚本、端口等）
   - 如果不能运行时验证 → 执行静态代码分析
   - 如果可以 → 启动项目进行动态验证
2. **逐项验证**：根据技术方案中的验收标准逐一验证
3. **记录结果**：记录每项的验证结果

### 运行时验证
- 启动项目服务
- 根据功能点逐一操作验证
- 检查返回结果、日志、界面等

### 静态代码分析
- 检查关键方法的实现
- 验证关键逻辑是否正确
- 检查是否有明显的代码问题

## 输出格式

请输出一个 JSON 对象，结构如下：

```json
{
  "verifyResult": {
    "verificationType": "runtime|static",
    "overallResult": "passed|failed",
    "checks": [
      {
        "criteria": "验收标准描述",
        "result": "passed|failed",
        "evidence": "验证依据（截图、日志、代码片段等）",
        "notes": "备注"
      }
    ],
    "issues": ["发现的问题列表"],
    "summary": "验证总结"
  }
}
```

## 注意事项
- 验证要基于技术方案的验收标准，不要凭空添加标准
- 运行时验证时注意启动时间和端口占用问题
- 发现的问题要记录清楚，方便后续修复
